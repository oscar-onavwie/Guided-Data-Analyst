# Synthetic sample datasets

All records are **fictional**, generated by `scripts/generate_sample_data.py` with fixed random seeds (re-running it produces identical files). Each dataset contains deliberate patterns so the app's results can be checked against known answers; `backend/tests/test_sample_datasets.py` pins them.

| File | Rows | What is planted | Expected result in the app |
|---|---|---|---|
| `small_business_sales_expenses.csv` | 368 | One transaction per day of 2025; sales grow ~5% a month; every 4th row has no payment method; two refunds (negative amounts); 3 exact duplicate rows appended | 3 duplicates (confirmed issue); `payment_method` 91 missing; 2 negative values (potential issue + finding); upward trend finding |
| `retail_product_performance.csv` | 200 | 5 categories × 4 regions; Electronics priced ~6× other categories; discounts written as `20%`; two extreme bulk orders (rows P038, P152); a constant `currency` column | `currency` flagged constant; `units_sold` has ≥2 extreme outliers (max 2,551); strong `units_sold`–`revenue` association; Electronics holds the largest share of revenue |
| `workforce_operational_performance.csv` / `.xlsx` | 260 | 52 weeks × 5 support teams; absence rises with overtime; team Delta resolves ~27% fewer tickets per agent; every 4th `csat_score` blank. The `.xlsx` has a second sheet (`Team Directory`) to exercise worksheet selection | `csat_score` 65 missing (25%); strong `overtime_hours`–`absence_days` association; Delta lowest average `tickets_resolved`; CSV and XLSX give identical statistics |

The demo mode in the app always labels these as **DEMO DATA**, including in exported report filenames (`DEMO-…`).
